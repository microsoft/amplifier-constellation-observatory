# Observatory 0.12.2

This release includes the interaction and management-observation fixes described
in [0.12.1](0.12.1.md), and adds an explicit local adoption path for an older
Observatory installation using its original Linux user systemd service.

Adoption preserves the original service definition, authentication, address,
configuration, data and support files. The owner accounts for unsettled effects
and stops the original service before the command verifies its absence. The
candidate starts through that same service and receives an update baseline only
after its identity is verified. Unknown results remain recorded and never
authorize an automatic retry. See [existing-service adoption](../existing-service-adoption.md)
for the supported unit shape, private review bindings and recovery procedure.

Fresh desktop packages now pin the published Instance 0.22.7 bundle, which carries
Native Runtime 0.15.7. Each platform's archive and compiled source are fixed in
the package lock. The matching computer helper is version 0.3.1 because its fixed
installation requests embed those same package pins. This corrects the older
fresh-install bundle; it does not
silently replace the instances or models already connected to Observatory.

The adoption path does not enroll an Instance service or change the engines, models or
installations already connected to Observatory. Subsequent application updates
retain the original manager and preserve existing work when an exact Busy reply
arrives before shutdown. Modified service definitions and unsupported platforms
refuse adoption without changing their configuration.

For published packages, consult the release assets for fresh-install bundle
provenance and package qualification. An existing installation's preserved
support and remote connections are separate from the bundle used for a fresh
installation. Existing
unsigned-package limits remain; hosted checks do not establish clean-machine,
signing or notarization acceptance.
