# Observatory 0.10.0

Add a computer by downloading its helper from Observatory, opening it and entering
a short-lived code. The computer appears on the existing canvas after pairing;
a fresh heartbeat shows when it is reachable. Windows x64, Apple-silicon and Intel
Mac, and Linux ARM64 and x64 helper packages accompany this release.

The helper makes outbound HTTPS connections and keeps a private identity for this
Observatory. It needs no SSH keys, incoming control port or central account.
Codes expire, attempts are limited, and a lost reply reuses the original request.
Revoking access preserves the computer record and its agents. Sleeping computers
remain saved and are shown as unreachable when observations grow stale.

Pairing grants computer observation only. It does not discover private agents,
install software, expose a shell or authorize additional operations. Existing
local and SSH recipes remain available through advanced setup. The helper uses
current-user startup and reports when enabling it fails.

The target computer must be able to reach Observatory over its LAN or private
network. Observatory hosting remains Linux. Helper packages are currently
unsigned; signing, notarization and consumer first-launch qualification remain
separate work. Do not disable operating-system protections to launch them.

Validation covers real TLS server/helper pairing, reply-loss recovery, scoped
credentials, revocation, archive integrity and desktop/mobile browser journeys.
Platform CI builds the native helpers and checks registration/removal of unique
current-user startup entries; this is distinct from a consumer sign-in or OS
security-warning test. No agent session, model call or world action is needed to
pair a computer.
