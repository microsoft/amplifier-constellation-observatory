# Observatory 0.7.0

Talk accepts more information while an agent works. Send a correction, answer or
follow-up without cancelling the current turn or dismissing its approval.

- Capable ACP agents receive ordered, deduplicated steering with an existing
  session; other agents receive a saved FIFO queue after the current prompt.
- Delivery labels distinguish local acceptance, remote receipt, model
  incorporation and uncertainty. Browser refresh preserves drafts and pending
  approvals. Retrying a lost HTTP acknowledgment reuses the same message ID.
  Provider-queued input stays uncertain at turn completion unless incorporation
  is confirmed; delayed receipt acknowledgments cannot erase that distinction.
- Explicit recovery reconnects to the saved session and uses advertised receipt
  acknowledgment methods. It never resends uncertain input, and works without
  starting a new prompt. Stop remains independent of sending.
- Pending messages preserve their original authorization. Revoked/expired
  credentials and changed endpoints cannot silently start queued work.
- ACP reads retain partial frames while handling updates. Permission waits no
  longer block incoming progress or steering receipts.

This is client intake support, not a guarantee that every provider can alter an
already running model call. The runtime determines the next legal incorporation
boundary. Generic ACP requires no extension. See [the public contract](../contracts.md#conversations).

Validation covers asynchronous subprocess and HTTP regressions plus real
Chromium tests. No live model, account or messaging access is required by CI.
